## 3. 四色法则的实际落地

```
#2600FD  主行动 · 品牌 · 正向数值 · 活跃态
#0A0A0B  体量 · 数据面板 · 字体 · 结构
#FFBF00  注意力 · 警示 · 强调
#FFFFFF  画布
```

调色板重映射规则：

| 原有的色系 | 映射到 | 理由 |
|---|---|---|
| `gray` `zinc` `slate` `neutral` `stone` | 墨阶（11 级） | 所有中性色收敛成一条墨阶 |
| `blue` `indigo` `violet` `purple` `cyan` `sky` `teal` `green` `lime` `emerald` | 蓝阶 | 所有冷色收敛成品牌蓝 |
| `amber` `yellow` `orange` | 黄阶 | 所有暖色收敛成信号黄 |
| `red` `rose` `pink` | 墨阶 | **亏损/危险在读作「墨」而非红** —— 这是四色法则下的刻意取舍 |

### 表面规则（解决「蓝 vs 黄」的正负号冲突）

蓝色压在黑色上对比度只有 2.4:1，不可读。所以「正向」由哪个颜色承担，取决于所在表面：

| 表面 | 正向 / 增益 | 注意 / 警示 |
|---|---|---|
| 白或纸面 | **蓝** | **黄** |
| 墨黑面板 | **黄** | **黄** |

例：白底持仓行 `+$1,284.20` 是蓝色；黑底英雄面板里的 `+2.74%` 是黄色。

# 第三轮：iPhone 17 Pro Max 安全边缘 + 移除深色模式

**提交：`5619da1`**

## 1. 左右留白统一到 iPhone 17 Pro Max 规格

**目标机型：** iPhone 17 Pro Max —— 440 × 956 pt 逻辑尺寸，regular width，竖屏左右安全区 0，横屏两侧各 62pt。

**做法：** 新增一个全站唯一的留白令牌，并**叠加真实硬件安全区**（而不是写死一个数字）：

```css
:root { --gutter-x: 24px; }

.px-gutter {
  padding-left:  calc(var(--gutter-x) + env(safe-area-inset-left, 0px));
  padding-right: calc(var(--gutter-x) + env(safe-area-inset-right, 0px));
}

@media (max-width: 380px) { :root { --gutter-x: 20px; } }
```

- iOS 在 regular width 下的标准内容边距是 20pt；这里取 **24px**，让四色面板更透气
- 叠加 `env(safe-area-inset-*)` 后，**横屏时会自动避开圆角与传感器区域**，而不是贴上去
- 窄于 380px 的机型回落到 20px，避免内容被挤

**应用范围：** 五个页面的最外层容器（Launcher / MyWealth / NoteDown / NewsHub / Settings）**以及子应用顶部栏**——所以标题和下方内容**左边缘严格对齐**。

改前的实际情况是各页不一致：Launcher 14px、NewsHub 12px、Settings 20px、MyWealth 12px。现在全部 24px。

**理由：** Ink & Signal 是**单色板系统**。真正的深色主题需要重新走一遍墨阶与对比度，而不是把这四个颜料机械反相——所以是移除，不是隐藏。

|---|---|
| `globals.css` | 删除 `prefers-color-scheme` 媒体查询、`.dark/html.dark` 令牌块、类覆盖块 |
| `App.tsx` | 删除主题 state、系统偏好监听、**两处**顶栏切换按钮；改为挂载时锁定 `light` 类 |
| `MyWealthApp.tsx` | 删除一个**声明了但从未在渲染中读取**的死 theme state |
| `GlobalSettings.tsx` | 删除「外观主题」控件与 `handleThemeChange`；备份导出里去掉 `mw_theme` 死键 |

## 居中：从"碰巧居中"改成"构造上居中"

原来用的是 flex + `justify-around`。它**只在两侧项目宽度完全相同时**才居中——一旦以后某一侧加了标签或改了宽度，Home 就会偏。

现在改成 **5 列等宽网格**，每一项在自己的轨道内居中。Home 占中间那条轨道，所以**它在数学上必然位于胶囊中心**，与两侧内容宽度无关。

另外把抬起方式从负 margin 改成 `-translate-y`——负 margin 会参与网格行高计算，transform 不会。

