## 3. 关键架构发现

### 3.1 技能引擎是「可搬运」的

`AskApptify.tsx` 里的 `executeAction(intent, data)`（约 470 行）**不依赖任何父组件状态**。它只做两件事：

```
读 → localStorage.getItem('mw_data_main' / 'apptify_notes' / 'apptify_tasks')
写 → localStorage.setItem(...) + dispatchEvent('apptify_data_changed')
```

只有**导航类意图**需要外部能力（`setCurrentApp`）。

**结论：** 可以把整套引擎抽到 `src/services/skillExecutor.ts`，让新旧两套界面共用，而不是把 1164 行的组件复制一份。这是本次重构最重要的决定——**复制组件会立刻产生两份需要同步维护的技能逻辑**。

### 3.2 「操作每一项任务」的地基已经存在

`skillRegistry.ts` 已有 3 组技能，带参数定义与中英例句：

| 技能组 | 意图 |
|---|---|
| MyWealth | `ADD_MONEY` `WITHDRAW_MONEY` `TRANSFER_MONEY` `ADD_BUDGET` `ADD_LOAN` `REPAY_LOAN` `QUERY` |
| NoteDown | 笔记与任务的增删改 |
| System | 页面导航 |

要满足「每一项任务」，需要扩到：账户增删改、预算项增删改、贷款增删改、持仓买卖、笔记/任务完整 CRUD、专注计时、新闻源管理、设置项、主题/语言。**每一个意图都需要在 `executeAction` 里配一个处理器**，这是独立的一条工作流。

### 3.3 多模态与记忆的底层已经在

- `aiService.chat(model, key, prompt, systemInstruction, images[])` —— **看图片已经通了**
- `aiService.embeddings(model, key, input)` —— **向量召回的地基已经在**
- Google Drive BYOS 同步 —— **跨设备记忆的地基已经在**

## 4. 形象设计（已完成）

按你给的图精确测量（源图 462×444）：

```
身体圆角    21.6%        眼睛对总宽   46.5%（占身体宽）
单眼宽      17.3%        单眼高       43.9%（占身体高）
双眼间距    11.9%        （用 space-between 实现，保证任意尺寸下几何不变）
```

**重绘为 DOM 而非贴图**——只有这样眼睛才能真正变形。全部表情只动两个可动画属性：`transform` 与 `border-radius`，因此：

- 每种表情变换都是 **GPU 合成**，不触发重排
- 表情**可在中途被打断**并平滑接续（不会跳帧）
- 单一组件服务全部尺寸（28px 到 160px 均已验证）

| 表情 | 实现 |
|---|---|
| `idle` | 基础竖椭圆 + 4.4s 呼吸缩放 |
| `blink` | `scaleY(0.07)`，随机 2.2–6s 触发一次，持续 140ms |
| `think` | 视线右上偏移 + 近眼收窄至 62%（眯眼，不是压扁色块）+ 三点环绕 |
| `happy` | 圆角改为 `50% 50% 0 0 / 100% 100% 0 0` —— **完整上拱弧**，身体上浮 5% |
| `sad` | 反拱 `0 0 50% 50% / 0 0 100% 100%` + 眼角外垂 13° |
| `listen` | 眼睛放大 8%，外圈 1px 脉冲环 |
| `speak` | 双眼错相 150ms 的 900ms 脉动，避免静态感 |

自动眨眼由组件自己管理：**只在外部持有 `idle` 时运行**，因此永远不会和刻意指定的表情打架。`prefers-reduced-motion` 下全部静止。

# 第九轮：助理本体 + 技能补全

**提交：`e48cdee` 及后续**

## 已交付

| 组件 | 作用 |
|---|---|
| `BingGoHomeCard` | 主页入口。**刻意非居中**——角色在左、文案与入口在右。快捷 chips 是真入口，点了会带着任务打开助理 |
| `BingGoFab` | 全站悬浮召唤。**用角色本身而不是通用图标**——它等待时会眨眼 |
| `BingGoAssistant` | 一个面板两种模式，共用同一个 phase 状态机：chat（记录/输入/图片/麦克风）与 call（角色独占一屏 + 状态行） |

**没有做深色。** 参考图是深色通话页，但本 App 是白底四色系统，深色面板会像一个外挂的另一个产品。通话模式靠**清空装饰**获得自己的空间，而不是靠反转配色。

## 技能补全（要求 9）

**发现并修复的既有 bug：** 注册表自始就声明了 `ADD_BUDGET` / `ADD_LOAN` / `REPAY_LOAN` / `SEARCH_NOTES`，但引擎**从未实现**它们，而兜底会返回「命令已处理。」——**对用户撒谎**。

新增处理器：`ADD_BUDGET` `ADD_LOAN` `REPAY_LOAN` `SEARCH_NOTES` `QUERY_NOTES` `UPDATE_NOTE` `DELETE_NOTE` `DELETE_TASK`。
兜底改为**如实回报未执行**，并验证它确实不改动任何数据。

## 又一个既有 bug：跨页字段不匹配

引擎写入 `tag`，而 NoteDown 读 `category` → `CATEGORY_MAP[undefined]` → **整页崩溃**。通过 AI 建的笔记一直会让 NoteDown 挂掉。

两侧都修了：引擎同时写两个字段；NoteDown 对未知类别**防御性兜底**（不认识的类别渲染成中性标签，而不是让页面挂掉）。

# 第十一轮：去掉白盘、精简卡片、可抚摸

| 要求 | 做法 |
|---|---|
| 悬浮按钮**不要白色外框** | 连白色圆盘一起去掉。现在是**纯角色本身 + 投影**，投影是 `drop-shadow` 加在角色上，所以阴影跟随它的圆角方形轮廓，而不是画一个圆 |
| 主页**删减信息、角色放大** | 删掉能力磁贴 ×3、事实行 ×2、内嵌面板。角色从 62px 放大到 **112px**。保留：名字、一句说明、3 个请求 chips、一个主按钮 |
| 加一点**互动感** | 角色可点击抚摸：变高兴表情（眼睛弯成上拱弧）+ 身体左右摇摆挤压，约 0.9 秒后复位。有蓝色小字 `TAP TO SAY HI` 提示可点。**键盘也能触发**（Tab 聚焦 + Enter/Space） |

抚摸会**覆盖任何当前表情**——因为它是用户直接触碰的回应，不该被状态机吞掉。

## 一个必须说明的取舍

去掉白色圆盘后，悬浮球在**蓝色磁贴上方会蓝压蓝**，只能靠投影区分。

我加强了投影（紧实深色边影 + 宽柔提升影），在当前实现下是可辨认的，但**不如有白盘时清晰**。这是「不要白框」的必然代价。

如果你觉得在某些位置看不清，有两个一行的选择：
1. 给角色加一圈**紧贴轮廓的白色描边**（不是白盘，是贴纸边）
2. 换一个悬浮位置，避开卡片内容
